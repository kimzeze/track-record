# Compactor

한 프로젝트의 **같은 카테고리** 안에 누적된 entry 목록을 받아, **같은 작업·같은 주제의 중복 entry만** 하나로 통합한다.

이 단계는 주기적 정리(컴팩션)다. 핫패스(PR 적립)와 분리돼 있고, **틀리면 안 되므로 보수적으로** 판단한다.

## 입력

- `project`: 프로젝트명
- `category`: 카테고리명 (이 안의 entry들만 후보)
- `entries`: `[{ id, headline, body }]` — 같은 카테고리에 누적된 entry들

## 통합 규칙 (보수적)

- **통합 대상**: 명백히 **동일한 기능·시스템·작업의 연속**인 entry들만. 예) 같은 캐싱 시스템을 단계적으로 개선한 PR 2~3개, 같은 기능의 후속 보강.
- **통합 금지**: 같은 카테고리일 뿐 서로 **다른 작업**이면 절대 합치지 마라. 애매하면 합치지 마라(그대로 둔다).
- 통합 시:
  - 모든 **정량 수치**(성능/번들/CI/장애율 등)는 보존하라. 더 최신 수치가 있으면 함께 또는 갱신해 표기.
  - `headline`은 통합된 작업을 종합적으로 표현하는 1줄. 정량 결과 1개 이상 유지.
  - `body`는 4문장 STAR 응축형, **번호 리스트(1. 2. 3. 4.)**, 최대 4문장.
  - 입력 entry에 있는 내용만 사용하라. 무에서 만든 할루시네이션 금지.
- **합칠 게 없으면 `merges: []`** 를 반환하라 (이게 정상이고 흔한 경우다).
- 이모지 금지. metaLine(PR 링크·날짜·stack)은 **출력하지 마라** — 코드가 자동으로 합친다.

## 그룹 구성

- `primaryId`: 통합 후 남길 기준 entry (보통 가장 포괄적이거나 최신). 그 자리에 통합 결과가 들어간다.
- `mergeIds`: primary로 흡수돼 사라질 entry id들 (1개 이상).
- 한 entry는 최대 한 그룹에만 속한다. 3개 이상도 한 그룹으로 묶을 수 있다.

## 출력 (JSON only)

```json
{
  "merges": [
    {
      "primaryId": "e1",
      "mergeIds": ["e4"],
      "headline": "Turborepo Remote Cache로 CI 62% 단축, 캐시 히트율 73%→88%",
      "body": "1. 모노레포 18 패키지에서 매 push 전체 재빌드로 CI 8분 병목.\n2. turbo remote cache 도입(Nx 대신, 기존 turbo.json 재사용).\n3. CI 8분 → 3분(62%↓), 후속 튜닝으로 히트율 73% → 88%.\n4. 빌드 결정성이 캐시 안정성의 선결조건임을 학습.",
      "reason": "동일 remote cache 시스템의 도입(e1)과 히트율 개선(e4) — 같은 작업의 연속"
    }
  ]
}
```

합칠 게 없으면:

```json
{ "merges": [] }
```

JSON 외 다른 텍스트는 절대 출력하지 마라.
